# 前言

C++ 中，内存的分配与释放都是由开发者自己手动实现的，但是往往会出现忘记释放内存或者多次释放内存的问题，因此 C++ 引入了智能指针。智能指针是一个类，它在析构时自动释放所管理的对象。

智能指针还是一种基于 RAII （资源获取即初始化，Resource Acquisition Is Initialization）技术的应用，

:::tip RAII
RAII （资源获取即初始化，Resource Acquisition Is Initialization）但是业界更倾向于叫它 SBRM (Scope-Bound Resource Management，基于作用域的资源管理)。

**通过利用 C++ 编译期对栈上局部变量极其严苛的生命周期管理，来强行绑定并管理堆上或其它类型的裸资源。**

:::

智能指针的实现主要有三种： `unique_ptr` 、 `shared_ptr` 和 `weak_ptr` 。

<!-- more -->

## `unique_ptr`

`unique_ptr` 是 C++11 引入的智能指针，它表示独占所有权，即一个 `unique_ptr` 只能管理一个对象，不能被复制或者共享。当 `unique_ptr` 被销毁时，它所管理的对象也会被自动释放。

```cpp
#include <memory>

class MyUniquePtr {
public:
    MyUniquePtr(int* ptr) : ptr_(ptr) {}
    ~MyUniquePtr() { delete ptr_; }

    MyUniquePtr(const MyUniquePtr&) = delete;
    MyUniquePtr& operator=(const MyUniquePtr&) = delete;

    MyUniquePtr(MyUniquePtr&& other) noexcept : ptr_(other.ptr_) {
        other.ptr_ = nullptr;
    }
    MyUniquePtr& operator=(MyUniquePtr&& other) noexcept {
        if (this != &other) {
            delete ptr_;
            ptr_ = other.ptr_;
            other.ptr_ = nullptr;
        }
        return *this;
    }

    int* get() const { return ptr_; }
}
```

## `shared_ptr`

`shared_ptr` 是 C++11 引入的智能指针，它表示共享所有权，即多个 `shared_ptr` 可以管理同一个对象，当最后一个 `shared_ptr` 被销毁时，所管理的对象才会被自动释放。

```cpp
class MySharedPtr {
public:
	MySharedPtr(int* ptr) : _ptr(ptr) {
		if (_ptr == nullptr) {
			_count = nullptr;
		} else {
			_count = new int (1);
		}
	}
	~MySharedPtr() {
		release();
	}

	MySharedPtr(MySharedPtr&&) = delete;
	MySharedPtr& operator=(MySharedPtr&&) = delete;

	MySharedPtr(const MySharedPtr& other) {
		_ptr = other._ptr;
		_count = other._count;
		if (_count != nullptr) {
			(*_count)++;
		}
	}
	MySharedPtr& operator=(const MySharedPtr& other) {
		if (this != &other) {
			release();
			_ptr = other._ptr;
			_count = other._count;
			if (_count != nullptr) {
				(*_count)++;
			}
		}
		return *this;
	}
	int* get() const { return _ptr; }

	int& operator* () const { return *_ptr; }
	int* operator-> () const { return _ptr; }

	int getcount() const { return _count == nullptr ? 0 : *_count; }

private:
	int* _ptr;
	int* _count;

	void release() {
		if (_count != nullptr) {
			(*_count)--;
			if ((*_count) == 0) {
				delete _ptr;
				delete _count;
				_ptr = nullptr;
				_count = nullptr;
			}
		}
	}
};
```

:::warning
一个裸指针只能被用来初始化 `shared_ptr` 一次，如果一个裸指针被多个 `shared_ptr` 管理，那么当其中一个 `shared_ptr` 被销毁时，所管理的对象就会被释放，导致其他 `shared_ptr` 访问已经被释放的对象，从而引发未定义行为。

正确做法应当是拷贝：

```cpp
int *a = new int(10);
MysharedPtr p1(a);
MysharedPtr p2(a); // [!code error] 错误用法
MysharedPtr p2(p1); // [!code ++]

// 或者
MysharedPtr p1(new int(10));
MysharedPtr p2(p1);
```
:::

## `weak_ptr`

`weak_ptr` 表示弱引用，即 `weak_ptr` 不拥有所管理的对象，它只是一个观察者，当最后一个 `shared_ptr` 被销毁时，所管理的对象会被自动释放，而 `weak_ptr` 仍然存在，但是它不再指向有效的对象。

`weak_ptr` 可以和 `shared_ptr` 相互转换，当需要访问 `weak_ptr` 所管理的对象时，可以使用 `lock()` 方法（原子操作）将 `weak_ptr` 转换为 `shared_ptr`，如果转换成功，则返回一个指向对象的 `shared_ptr`，否则返回一个空的 `shared_ptr`。

`weak_ptr` 主要用于解决循环引用的问题，当两个对象互相持有对方的 `shared_ptr` 时，就会导致循环引用，无法释放内存，而使用 `weak_ptr` ，不会增加 `shared_ptr` 的引用计数，从而避免了循环引用的问题。
